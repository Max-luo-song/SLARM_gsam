# SLARM 改进方向分析

记录时间：2026-09-13 11:25:58 UTC。

分析依据：当前工作区的模型、训练和评测代码、已有实验记录，以及相关原始论文与官方项目。本文记录分析与实验建议；分析过程中没有修改模型代码或启动训练。文件行号对应分析时的工作区版本，后续修改可能使其变化。

## 1. 总体判断

SLARM 有值得研究的改进空间，尤其是动态运动一致性、低速目标处理和流式记忆；但应先把实现问题、评测问题与真正的方法瓶颈分开，否则容易把修复代码后的涨点误认为科研创新。

SLARM 是驾驶场景的前馈动态重建与语义模型，输出高斯场景、运动和语义特征，并不直接输出自车规划轨迹或控制量。合理的研究目标是提升重建、运动估计、语义理解和在线处理能力；闭环驾驶收益需要另接规划器或仿真系统验证。

本文将结论区分为已确认的实现或设计事实、证据支持的疑似瓶颈，以及待实验验证的研究假设，不承诺所有指标同时提升。

## 2. 当前模型和实验基础

当前全量训练配置采用三路相机、4 个上下文时间步、160×240 输入、768 维特征和 12 层骨干。模型结合图像与相机几何信息，预测像素对齐的 3D Gaussians、三阶运动系数和语言对齐特征，再渲染目标视角与时间。

训练主要使用 RGB、深度、运动正则和 LSeg 特征蒸馏；配置开启 LPIPS，但从第 5000 步才加入。配置见 [training_waymo_full.sh](../training_waymo_full.sh)，相关训练参数从约第 81 行开始。

这里的“前馈”指不需要为每个测试场景重新优化参数，并不代表没有历史信息，也不自动代表严格实时因果推理。项目包含 `full`、`causal` 和 `window_3`，三者的信息条件不同。

已有实验需要这样理解：

- 单场景实验开启了 `OVERFIT_EXP`，训练与验证使用同一场景列表。这适合测试拟合能力，不能证明跨场景泛化。
- 核对全量数据标注后，确认有 798 个训练场景、202 个验证场景，按 `scene_name` 检查没有交集。
- 本次读取时，全量实验日志最大记录到第 500 步，尚未发现该实验的评测结果，不能据此判断完整训练后的性能。这是读取时的快照，不代表训练之后的状态。

单场景训练与验证共用列表的逻辑见 [constants.py](../src/dataset/constants.py)，约第 31 行。

为避免比较不同训练步数，以下统一读取六个单场景实验在第 24999 步的结果：

| 场景 | 模式 | PSNR ↑ | 动态区域 PSNR ↑ | Flow EPE ↓ |
|---|---|---:|---:|---:|
| 080 | full | 29.5772 | 26.9894 | 0.1459 |
| 080 | causal | 27.3799 | 24.7537 | 0.2892 |
| 080 | window_3 | 26.6109 | 24.2265 | 0.2872 |
| 621 | full | 30.8801 | 26.2363 | 0.1577 |
| 621 | causal | 31.2840 | 26.3902 | 0.2048 |
| 621 | window_3 | 31.2867 | 26.3152 | 0.2065 |

原始记录位于 [work_dirs/slarm](../work_dirs/slarm)，各实验的 `eval_results/eval_24999.txt` 和 `eval_24999_flow.txt`。

这组结果支持两个有限结论：流式模式的运动估计值得重点检查；RGB 提升与运动精度提升并不一致。场景 621 中，流式模式 PSNR 更高，EPE 却更差。不过，这只有两个过拟合场景，且模式同时改变了注意力和渲染规则，不能归因于某一个模块。

## 3. 主要问题与证据

### 3.1 流式结果的时间含义与当前时刻在线感知不同

**性质：已确认的设计事实。**

在流式渲染中，动态高斯主要向过去传播；推理脚本用相邻两个上下文帧的预测重建中间时间段。例如，默认观测间隔为 5 帧，重建第 1～4 帧时会用到第 5 帧生成的动态高斯。

代码证据：

- [slarm.py](../src/models/slarm.py)，约第 1086 行的运动与时间掩码。
- [inference_stream.py](../inference_stream.py)，约第 282 行的流式切片逻辑。

[SLARM 原论文](https://arxiv.org/html/2603.22893v1)也明确描述了回溯重建方式。它适合对刚刚经过的场景进行延迟重建，但不能直接代表“时刻 t 只看截至 t 的数据，立即得到同等质量的结果”。以 10 Hz、间隔 5 帧为例，中间帧需要等待后续观测，等待时间本身就可能达到数百毫秒，还未包含计算时间。

另外，数据集默认 `only_interp=True`，主要训练观测区间内插值，不能把插值性能当作未来外推能力。

建议将评测拆成三种任务：

| 任务 | 允许的信息 | 要回答的问题 |
|---|---|---|
| 离线插值 | 目标时刻前后的观测 | 场景重建质量如何？ |
| 延迟回溯 | 当前观测与历史，重建过去 | 多大等待时间换来多少质量？ |
| 当前感知／未来外推 | 截至当前的观测 | 立即输出和短期预测是否可靠？ |

这既是评测前提，也可能产生一个有价值的研究方向：缩小回溯重建与严格因果动态感知之间的差距。

### 3.2 流式缓存存在实现缺陷，常规评测未覆盖完整流式路径

**性质：已确认的工程问题；对模型实际指标的影响尚待验证。**

`StreamSession._update_cache()` 使用“当前缓存长度除以窗口大小”估计每帧 token 数，并从第一帧起删除这部分 token。窗口还没装满时，这会把一帧内部截断。

提取实际方法，使用模拟缓存做了不加载模型的验证。假设每帧 1800 个 token、窗口大小为 3：

| 已处理帧数 | 当前代码保留 token | 按完整帧窗口应保留 |
|---|---:|---:|
| 1 | 1200 | 1800 |
| 2 | 2000 | 3600 |
| 3 | 2534 | 3600 |

这里应保留最多两帧历史，供下一帧构成三帧窗口。代码见 [stream_session.py](../src/models/stream_session.py)，约第 79 行。

另外：

- 即使采用窗口缓存，`_update_predictions()` 仍持续拼接历史高斯和特征，完整会话的存储并非恒定。
- 推理入口直接执行 `int(args.mode.split('_')[-1])`，传入纯 `causal` 会解析失败。见 [inference_stream.py](../inference_stream.py)，约第 109 行。

这些问题不能用来解释前述实验表中的全部性能差距。常规评测调用的是批量 `model(input_dict)`，没有走 `StreamSession` 的缓存更新路径。

合理顺序是先修复并验证缓存边界、模式解析和历史结果保留策略，再研究更好的记忆机制。修复收益应作为工程收益单独报告。

### 3.3 动态运动监督存在歧义，低速目标受到硬阈值限制

**性质：运动歧义是疑似方法瓶颈；速度截断与评测筛选是已确认事实。**

当前模型对每个像素对应的高斯预测三阶运动系数，通过渲染监督学习运动。这个设计表达能力强，但“画面对齐了”不一定说明“物体运动估对了”。

深度、运动、透明度和尺度可以共同补偿渲染误差。如果同一辆车在不同视角和不同帧生成的高斯运动不一致，模型仍可能得到不错的 RGB 指标。当前启用的损失中，没有看到显式约束这些对应高斯运动一致性的项。

代码证据：

- [slarm.py](../src/models/slarm.py)，约第 760 行的运动预测。
- [losses.py](../src/utils/losses.py)，约第 1059 行的运动正则。

推理时存在如下速度截断：

```python
forward_v_batched[forward_v_batched.norm(dim=-1) < 1.0] = 0.0
```

低于 1 m/s 的预测速度直接归零；流式静动态划分也使用同量级硬阈值。见 [slarm.py](../src/models/slarm.py)，约第 1091～1110 行。

这可能影响缓慢起步、低速跟车、缓慢行走等情况。但直接删除阈值也可能放大静态背景的虚假运动，不能预设一定涨点。

现有 flow 评测还只纳入“该时间样本中存在 GT 速度大于 1”的样本。这不是删除所有低速点，而是会遗漏整段只有低速运动的样本。见 [engine_tools.py](../engine_tools.py)，约第 639 行。

建议增加按速度分组的评测，同时报告静态误报与动态漏报。

### 3.4 语义训练与评测有改进空间

**性质：包含已确认的可选分支问题，以及待验证的监督瓶颈。**

当前 GPU 默认采用 RGB 与语义特征拼接渲染，语义梯度能够回传到几何。存在 `detach()` 的独立渲染分支没有默认启用，不能算作当前训练缺陷。

值得检查的问题包括：

- 当前使用逐像素特征 MSE，没有显式处理教师在遮挡边界、远处小目标上的不可靠预测。
- 教师特征做了归一化，学生输出没有同样的显式约束，分类又采用点积与固定温度。特征模长可能影响概率阈值行为，需要实验验证。
- 可选 `cls_prob` 分支在默认已经求均值的交叉熵后，再除一次像素数。这是明确的额外缩放问题，但当前 MSE 配置不会触发它。见 [losses.py](../src/utils/losses.py)，约第 1136 行。
- 当前 mIoU 是逐时间样本计算后平均，不等于全数据集累计混淆矩阵后计算的 mIoU。应保留原指标，同时补充统一统计与逐类 IoU。见 [engine_tools.py](../engine_tools.py)，约第 796 行。

此外，评测数据加载失败时会尝试返回另一个场景，评测样本列表还包含硬编码跳过项。这些不一定已影响现有结果，但需要记录实际成功评测的场景与时间戳，防止不同方法评到不同样本。见 [datasets.py](../src/dataset/datasets.py)，约第 722 行及评测数据集构造部分。

## 4. 最值得推进的三个科研方向

| 优先级 | 方向 | 主要收益目标 | 实现／训练成本 | 当前判断 |
|---|---|---|---|---|
| 1 | 可见性感知的跨帧运动一致性 | Flow EPE、动态重建、时间稳定性 | 中等；可主要增加训练成本 | 最值得先验证 |
| 2 | 动静分离的有界流式记忆 | 长序列质量、遮挡恢复、显存与延迟 | 中高 | 系统价值高，但已有工作较多 |
| 3 | 可靠性加权的时空语义蒸馏 | 小目标 IoU、语义稳定性、部分运动指标 | 中等 | 改善有可能，新颖性需严格论证 |

### 4.1 可见性感知的跨帧运动一致性

核心研究问题：同一个空间点，从不同帧出发预测到同一目标时刻，能否得到一致的位置和运动？

设两个对应高斯分别来自时刻 a、b，其位置和运动函数为 μ_a、Γ_a 与 μ_b、Γ_b，可约束：

```text
L_motion_consistency
  = w_vis · ρ(μ_a + Γ_a(t-a) - μ_b - Γ_b(t-b))
```

其中 `w_vis` 表示可见性权重，`ρ` 表示稳健误差函数。关键不在公式本身，而在于：

- 如何建立对应关系，避免把遮挡前后的不同物体连起来。
- 如何获得可见性权重，避免所有困难样本都被降权。
- 如何对静态、刚体运动与非刚体运动采用不同约束。
- 在不同时间原点下，应比较共同目标时刻的运动，不能直接要求三阶系数相等。

最小版本可以只增加训练约束，保留当前推理结构。之后再考虑轻量软动态门控，替代统一的 1 m/s 截断。主要涉及运动预测、训练损失，以及训练时建立几何对应关系的辅助逻辑。

预期改善运动与动态区域质量的一致性；风险是错误对应损害行人肢体等非刚体运动，或者模型通过压低透明度逃避约束。

科研上不能只写“加入运动一致性”。[PointForward](https://wm-research.github.io/PointForward/) 已研究点对齐表示与实例运动一致性，[C4G](https://cvlab-kaist.github.io/C4G/) 已研究紧凑高斯与全局运动。更值得聚焦的差异是：SLARM 的多时间锚点高阶运动，在因果、遮挡与低速条件下如何保持一致。这仍是待验证的贡献切入点，不是已确认的新颖性结论。

### 4.2 动静分离的有界流式记忆

目前窗口缓存按时间裁剪，没有利用“静态背景可长期复用、动态内容需要更新”的差别。

可以设计固定总预算：

- 静态部分存储经过几何对齐和压缩的长期信息。
- 动态部分保留近期运动信息。
- 按新观测、可见性与运动置信度更新或淘汰。
- 明确区分推理必要状态与用于导出视频的历史结果。

需要修改骨干的缓存接口与 `StreamSession`。预期改善长序列、再出现目标和多视角一致性；风险是错误动静划分导致残影，以及关联开销抵消加速收益。

这一方向已有很近的工作：[StreamVGGT](https://wzzheng.net/StreamVGGT/) 使用因果注意力与缓存，[STAC](https://arxiv.org/abs/2603.20284) 已研究时间重要性和空间压缩。仅增加缓存压缩或长期 token 不足以形成强创新，需要证明针对动态场景的记忆更新确实优于这些通用策略。

### 4.3 可靠性加权的时空语义蒸馏

将当前所有像素同等拟合教师特征的监督，改成结合几何可见性和跨帧一致性的监督：

- 教师一致且可见的区域，强化语义与运动约束。
- 遮挡、新出现区域或教师不一致区域，采用稳健监督。
- 对小目标和语义边界单独统计与适度平衡。
- 保留开放词汇能力，避免只对固定类别过拟合。

可以先只改训练损失，推理基本不增加成本。主要风险是教师高置信度地犯错，以及过强的时间平滑抹去真实变化。

SLARM 本身已经提出语义蒸馏改善运动估计，因此“增加语义监督”不能作为新贡献。需要验证的是如何识别错误监督，以及如何让语义、运动和可见性相互校验。相关基础见 [SLARM 原论文](https://arxiv.org/html/2603.22893v1)。

## 5. 推荐实验路线

### 阶段一：建立可信基线

保留原始实现结果，另建修复后的基线；分别检查缓存帧边界、真实流式执行、语义统计和评测样本清单。修复收益单独报告。

批量因果推理与缓存推理还涉及历史特征更新方式，不能简单要求全序列结果逐元素完全相同。应先明确对应的信息与状态更新协议，再设计等价性检查。

### 阶段二：低成本瓶颈检查

在现有模型上按速度、距离、遮挡和动态类别分组，比较预测归零前后的 flow，检查不同时间锚点的运动一致性。

阈值选择只用开发集，固定后再评测。如果低速问题只占极少误差，就不将其作为主方向。

### 阶段三：多场景小规模验证方向一

固定训练子集和独立开发场景，做四组实验：

1. 基线。
2. 仅一致性。
3. 仅可见性处理。
4. 一致性与可见性处理结合。

先不加入新骨干、额外教师或更多数据，避免无法解释收益。

### 阶段四：完整训练与消融

达到验证门槛后，用完整训练集训练，对独立保留场景评测，并以 3 个随机种子检查稳定性。对场景做配对统计或 bootstrap，避免把同一视频的大量相邻帧当作独立证据。

至少同时报告：

| 能力 | 指标 |
|---|---|
| 重建 | PSNR、SSIM、LPIPS，区分全图、非天空和动态区域 |
| 几何 | Depth RMSE，按距离和动态区域分组 |
| 运动 | EPE、准确率、速度分组、静态误报 |
| 语义 | 数据集级 mIoU、逐类 IoU、时间一致性 |
| 在线性能 | 观测等待时间、端到端 P50/P95 延迟、峰值显存、序列长度增长曲线 |

训练比较固定数据、初始化、分辨率、监督与样本曝光量，并报告实际算力成本。使用额外标签或教师的实验单独比较。

方向一的失败判据应提前明确：如果收益只出现在过拟合场景，或仅 PSNR 上升而运动误差不降，或依赖过滤更多困难样本，那么“改善动态运动建模”的假设就没有得到支持。

## 6. 首选建议

先修复流式工程问题并完善分组评测，然后验证“可见性感知的跨帧运动一致性”。它最贴近当前代码暴露出的运动歧义，能够争取同时改善运动与动态重建，而且最小版本可以保留现有前馈推理成本。

能否涨点、是否足以形成论文贡献，需要上述实验决定。重建和感知指标的提升，也不能代替后续闭环驾驶评测。
